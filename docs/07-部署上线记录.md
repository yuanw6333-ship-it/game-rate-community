# GameRate 部署上线记录

本文档用于记录 GameRate 的部署计划、部署步骤、上线检查和后续运维事项。当前阶段只做部署规划，不进行真实部署。

## 1. 本地开发环境

本地开发阶段需要准备以下环境：

| 环境 | 用途 |
|---|---|
| JDK | 运行和构建 Spring Boot 后端 |
| Maven | 管理后端依赖和打包 |
| MySQL | 保存业务数据 |
| Redis | 缓存预留，V1 前期可暂不强依赖 |
| Node.js | 运行和构建 Vue 3 前端 |
| 微信开发者工具 | 后续开发和预览微信小程序 |

建议版本后续在实际初始化工程时确定，并写入 README。

## 2. 后端部署计划

### 2.1 打包 Spring Boot jar

计划使用 Maven 打包后端项目：

```bash
mvn clean package
```

打包产物预计位于：

```text
gamerate-backend/target/*.jar
```

### 2.2 上传服务器

将 jar 文件上传到服务器应用目录，例如：

```text
/opt/gamerate/backend/
```

### 2.3 配置 application-prod.yml

生产环境配置需要包含：

- 服务端口。
- MySQL 连接地址。
- MySQL 用户名和密码。
- Redis 连接地址。
- 文件上传路径。
- JWT 或 Token 密钥。
- 日志路径。

注意：生产配置不得提交到 Git，敏感信息使用服务器本地配置或环境变量维护。

### 2.4 启动后端服务

V1 可以先使用 `nohup` 启动：

```bash
nohup java -jar gamerate-backend.jar --spring.profiles.active=prod > app.log 2>&1 &
```

后续建议改为 `systemd` 管理服务，便于开机自启、停止、重启和查看状态。

## 3. 前端部署计划

### 3.1 Vue 打包

Web 用户端和后台管理端分别打包：

```bash
npm run build
```

打包产物通常为：

```text
dist/
```

### 3.2 上传服务器

建议上传到 Nginx 静态资源目录：

```text
/opt/gamerate/web/
/opt/gamerate/admin/
```

### 3.3 Nginx 配置静态资源

Nginx 需要配置：

- Web 用户端静态资源路径。
- 后台管理端静态资源路径。
- 后端 API 反向代理。
- 前端路由 history 模式回退。
- HTTPS 证书。

示例规划：

```text
https://example.com/          -> gamerate-web
https://admin.example.com/    -> gamerate-admin
https://api.example.com/api/  -> gamerate-backend
```

## 4. 数据库部署计划

### 4.1 创建数据库

在服务器 MySQL 中创建 `gamerate` 数据库。

### 4.2 执行 SQL 脚本

按顺序执行：

```text
sql/01-init-schema.sql
sql/02-init-data.sql
sql/03-test-data.sql
```

正式环境不建议执行测试数据脚本，除非明确用于演示环境。

### 4.3 初始化基础数据

基础数据包括：

- 默认管理员。
- 游戏分类。
- 游戏标签。
- 必要的平台或枚举数据。

上线前必须修改默认管理员密码，不允许使用本地开发密码。

## 5. 小程序上线计划

### 5.1 配置接口域名

在微信公众平台配置合法请求域名，例如：

```text
https://api.example.com
```

接口必须使用 HTTPS。

### 5.2 微信开发者工具预览

- 导入小程序项目。
- 配置 AppID。
- 预览首页、游戏列表、详情、评分评论、收藏和个人中心。
- 检查接口请求是否正常。

### 5.3 提交审核

- 补充小程序基础信息。
- 检查隐私协议和用户数据使用说明。
- 提交微信审核。

### 5.4 发布上线

审核通过后发布上线，并记录版本号、发布时间和主要功能。

## 6. 后续运维计划

### 6.1 日志查看

- 查看后端应用日志。
- 查看 Nginx 访问日志和错误日志。
- 记录接口异常和慢请求。

### 6.2 数据备份

- 定期备份 MySQL 数据。
- 重要版本上线前手动备份。
- 保存数据库结构和基础数据脚本。

### 6.3 异常排查

- 检查应用进程是否运行。
- 检查端口是否开放。
- 检查 MySQL 和 Redis 是否可连接。
- 检查 Nginx 反向代理是否正确。
- 检查服务器磁盘、内存和 CPU。

### 6.4 版本更新记录

每次上线后记录：

- 上线时间。
- 上线版本。
- 修改内容。
- 执行人。
- 是否涉及数据库变更。
- 是否发生异常。
- 回滚方案。
