# GameRate 游戏评分社区 V1 数据库设计

## 1. 数据库设计目标

GameRate V1 数据库用于支撑游戏信息浏览、用户注册登录、评分、评论、收藏、排行榜、后台基础管理和后续外部游戏数据同步。

- 数据库名称：`gamerate`
- 数据库类型：MySQL
- 字符集：`utf8mb4`
- 排序规则：`utf8mb4_unicode_ci`
- 表关系：V1 使用普通索引和唯一索引表达主要关系，暂不强制添加物理外键，方便个人开发阶段初始化、重建和导入测试数据。
- 删除策略：核心业务表预留 `is_deleted` 字段，0 表示未删除，1 表示已删除。
- 时间字段：所有表都包含 `create_time` 和 `update_time`。

## 2. 核心表清单

| 表名 | 作用 |
|---|---|
| `user` | 保存普通用户账号、昵称、头像、简介和账号状态 |
| `admin` | 保存后台管理员账号、角色和账号状态 |
| `game` | 保存游戏基础信息、统计数据和外部数据来源信息 |
| `category` | 保存游戏分类，如动作、角色扮演、策略等 |
| `platform` | 保存游戏平台，如 PC、Steam、PlayStation 等 |
| `game_rating` | 保存用户对游戏的评分记录 |
| `game_comment` | 保存用户对游戏的评论记录 |
| `game_favorite` | 保存用户收藏游戏的记录 |

## 3. 表字段设计

### 3.1 user 用户表

作用：保存普通用户基础账号信息。普通用户可以浏览游戏、评分、评论和收藏。

| 字段 | 类型 | 说明 |

| `password_hash` | VARCHAR(100) | 加密后的密码 |
| `nickname` | VARCHAR(50) | 用户昵称 |
| `avatar_url` | VARCHAR(500) | 用户头像地址 |
| `email` | VARCHAR(100) | 邮箱，可为空 |
| `phone` | VARCHAR(20) | 手机号，可为空 |
| `bio` | VARCHAR(255) | 个人简介 |
| `status` | TINYINT | 状态：0禁用，1正常 |
| `last_login_time` | DATETIME | 最后登录时间 |
| `is_deleted` | TINYINT | 逻辑删除：0未删除，1已删除 |
| `create_time` | DATETIME | 创建时间 |
| `update_time` | DATETIME | 更新时间 |

索引：

- 主键索引：`id`
- 唯一索引：`username`

可扩展字段：

- `register_source`：注册来源

## 4. 表关系说明

| 关系 | 说明 |
|---|---|
| `game.category_id -> category.id` | 一个游戏对应一个主分类，一个分类下可以有多个游戏 |
| `game.platform_id -> platform.id` | 一个游戏对应一个主平台，一个平台下可以有多个游戏 |
| `game_rating.user_id -> user.id` | 一条评分属于一个用户 |
| `game_rating.game_id -> game.id` | 一条评分属于一个游戏 |
| `game_comment.user_id -> user.id` | 一条评论属于一个用户 |
| `game_comment.game_id -> game.id` | 一条评论属于一个游戏 |
| `game_favorite.user_id -> user.id` | 一条收藏属于一个用户 |
| `game_favorite.game_id -> game.id` | 一条收藏属于一个游戏 |

## 5. 统计字段维护说明

`game` 表中的 `average_score`、`rating_count`、`view_count`、`comment_count`、`favorite_count`、`hot_score` 是冗余统计字段，用于列表、详情和排行榜快速展示。

- 用户新增、修改、删除评分后，需要重新计算 `average_score` 和 `rating_count`。
- 用户查看游戏详情后，需要更新 `view_count`。
- 用户新增或删除评论后，需要更新 `comment_count`。
- 用户收藏或取消收藏后，需要更新 `favorite_count`。
- `hot_score` 后续可结合评分人数、评论数量、收藏数量和更新时间计算。

## 6. V1 暂不建表的内容

- 游戏标签多对多表：功能模块中保留标签方向，V1 数据库先不建独立标签表，后续可扩展 `game_tag` 和 `game_tag_relation`。
- 即时聊天相关表。
- 复杂动态流相关表。
- 支付订单相关表。
- 第三方账号绑定表。
- 复杂 RBAC 权限表。
- 游戏百科级多维资料表。
