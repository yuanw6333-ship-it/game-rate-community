# GameRate 游戏评分社区 V1 数据库设计

## 1. 数据库设计目标

GameRate V1 数据库用于支撑游戏信息浏览、用户注册登录、评分、评论、收藏、排行榜、后台管理和基础搜索。当前阶段优先保证结构清晰、便于个人开发和后续迭代，不追求一次性覆盖大型社区的全部数据模型。

建议数据库名称为 `gamerate`，数据库类型为 MySQL，字符集使用 `utf8mb4`。

## 2. 表清单

| 表名 | 作用 |
|---|---|
| `user` | 保存普通用户和管理员账号信息 |
| `game` | 保存游戏基础信息和统计数据 |
| `game_category` | 保存游戏分类 |
| `game_tag` | 保存游戏标签 |
| `game_tag_relation` | 保存游戏和标签的关联关系 |
| `game_score` | 保存用户对游戏的评分和短评 |
| `game_comment` | 保存用户对游戏的评论 |
| `game_favorite` | 保存用户收藏游戏的记录 |
| `admin_operation_log` | 保存管理员后台操作日志 |

## 3. 表字段设计

### 3.1 user 用户表

用于保存普通用户和管理员账号。V1 不单独拆复杂权限表，通过 `role` 区分普通用户和管理员。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT | 主键ID |
| `username` | VARCHAR(50) | 用户名，登录账号 |
| `password` | VARCHAR(100) | 加密后的密码 |
| `nickname` | VARCHAR(50) | 用户昵称 |
| `avatar` | VARCHAR(255) | 头像地址 |
| `bio` | VARCHAR(255) | 个人简介 |
| `role` | VARCHAR(20) | 角色：`user` 普通用户，`admin` 管理员 |
| `status` | TINYINT | 状态：0禁用，1正常 |
| `create_time` | DATETIME | 创建时间 |
| `update_time` | DATETIME | 更新时间 |

建议索引：

- 主键索引：`id`
- 唯一索引：`username`
- 普通索引：`role`、`status`

后续可扩展字段：

- `email`：邮箱
- `phone`：手机号
- `last_login_time`：最后登录时间
- `deleted`：逻辑删除标记

### 3.2 game 游戏表

用于保存游戏基础资料和常用统计数据，是游戏列表、详情、排行榜和搜索的核心表。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT | 主键ID |
| `name` | VARCHAR(100) | 游戏名称 |
| `original_name` | VARCHAR(100) | 游戏原名 |
| `cover_url` | VARCHAR(255) | 游戏封面地址 |
| `description` | TEXT | 游戏简介 |
| `developer` | VARCHAR(100) | 开发商 |
| `publisher` | VARCHAR(100) | 发行商 |
| `release_date` | DATE | 发行日期 |
| `platform` | VARCHAR(100) | 游戏平台，如 PC、Steam、Switch |
| `category_id` | BIGINT | 分类ID，关联 `game_category.id` |
| `average_score` | DECIMAL(3,1) | 综合平均评分 |
| `score_count` | INT | 评分人数 |
| `comment_count` | INT | 评论数量 |
| `favorite_count` | INT | 收藏数量 |
| `status` | TINYINT | 状态：0下架，1上架 |
| `create_time` | DATETIME | 创建时间 |
| `update_time` | DATETIME | 更新时间 |

建议索引：

- 主键索引：`id`
- 普通索引：`name`
- 普通索引：`category_id`
- 普通索引：`platform`
- 普通索引：`average_score`
- 普通索引：`favorite_count`
- 普通索引：`release_date`
- 普通索引：`status`

后续可扩展字段：

- `source`：数据来源
- `source_id`：第三方数据ID
- `official_website`：游戏官网
- `trailer_url`：宣传片地址
- `hot_score`：热度分
- `deleted`：逻辑删除标记

### 3.3 game_category 游戏分类表

用于保存游戏分类，例如动作、角色扮演、策略、冒险等。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT | 主键ID |
| `name` | VARCHAR(50) | 分类名称 |
| `description` | VARCHAR(255) | 分类说明 |
| `sort` | INT | 排序值，越小越靠前 |
| `status` | TINYINT | 状态：0禁用，1启用 |
| `create_time` | DATETIME | 创建时间 |
| `update_time` | DATETIME | 更新时间 |

建议索引：

- 主键索引：`id`
- 唯一索引：`name`
- 普通索引：`sort`
- 普通索引：`status`

后续可扩展字段：

- `icon`：分类图标
- `code`：分类编码
- `deleted`：逻辑删除标记

### 3.4 game_tag 游戏标签表

用于保存游戏标签，例如开放世界、多人联机、像素风、剧情向等。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT | 主键ID |
| `name` | VARCHAR(50) | 标签名称 |
| `status` | TINYINT | 状态：0禁用，1启用 |
| `create_time` | DATETIME | 创建时间 |
| `update_time` | DATETIME | 更新时间 |

建议索引：

- 主键索引：`id`
- 唯一索引：`name`
- 普通索引：`status`

后续可扩展字段：

- `description`：标签说明
- `sort`：排序值
- `deleted`：逻辑删除标记

### 3.5 game_tag_relation 游戏标签关联表

用于建立游戏和标签之间的多对多关系。一个游戏可以有多个标签，一个标签也可以对应多个游戏。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT | 主键ID |
| `game_id` | BIGINT | 游戏ID，关联 `game.id` |
| `tag_id` | BIGINT | 标签ID，关联 `game_tag.id` |
| `create_time` | DATETIME | 创建时间 |

建议索引：

- 主键索引：`id`
- 唯一索引：`game_id + tag_id`
- 普通索引：`game_id`
- 普通索引：`tag_id`

后续可扩展字段：

- `create_by`：创建人

### 3.6 game_score 游戏评分表

用于保存用户对游戏的评分，也可以保存一段短评。一个用户对同一游戏只能有一条评分记录。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT | 主键ID |
| `user_id` | BIGINT | 用户ID，关联 `user.id` |
| `game_id` | BIGINT | 游戏ID，关联 `game.id` |
| `score` | DECIMAL(3,1) | 评分，建议范围 0-10 |
| `content` | VARCHAR(500) | 评分短评，可为空 |
| `create_time` | DATETIME | 创建时间 |
| `update_time` | DATETIME | 更新时间 |

建议索引：

- 主键索引：`id`
- 唯一索引：`user_id + game_id`
- 普通索引：`game_id`
- 普通索引：`user_id`
- 普通索引：`score`

后续可扩展字段：

- `status`：评分状态
- `deleted`：逻辑删除标记

| `update_time` | DATETIME | 更新时间 |

建议索引：

- 主键索引：`id`
- 普通索引：`game_id`
- 普通索引：`user_id`
- 普通索引：`status`
- 普通索引：`create_time`

后续可扩展字段：

- `like_count`：点赞数
- `parent_id`：父评论ID，用于后续楼中楼
- `deleted`：逻辑删除标记

### 3.8 game_favorite 游戏收藏表

## 4. 表关系说明

| 关系 | 说明 |
|---|---|
| `user.id -> game_score.user_id` | 一个用户可以对多个游戏评分 |
| `game.id -> game_score.game_id` | 一个游戏可以有多条评分 |
| `user.id -> game_comment.user_id` | 一个用户可以发表多条评论 |
| `game.id -> game_comment.game_id` | 一个游戏可以有多条评论 |
| `user.id -> game_favorite.user_id` | 一个用户可以收藏多个游戏 |
| `game.id -> game_favorite.game_id` | 一个游戏可以被多个用户收藏 |
| `game_category.id -> game.category_id` | 一个分类下可以有多个游戏 |
| `game.id -> game_tag_relation.game_id` | 一个游戏可以绑定多个标签 |
| `game_tag.id -> game_tag_relation.tag_id` | 一个标签可以绑定多个游戏 |
| `user.id -> admin_operation_log.admin_id` | 管理员操作日志关联管理员用户 |

## 5. 统计字段维护说明

`game` 表中的 `average_score`、`score_count`、`comment_count`、`favorite_count` 是冗余统计字段，用于列表、详情和排行榜快速展示。

- 用户新增、修改、删除评分后，需要重新计算 `average_score` 和 `score_count`。
- 用户新增或删除评论后，需要更新 `comment_count`。
- 用户收藏或取消收藏后，需要更新 `favorite_count`。

V1 可以先在业务代码中同步更新统计字段，后续再根据数据量考虑异步任务或缓存方案。

## 6. V1 不做的数据库设计

- 不设计即时聊天相关表。
- 不设计复杂动态流相关表。
- 不设计支付订单相关表。
- 不设计第三方账号绑定表。
- 不设计复杂 RBAC 权限表。
- 不设计游戏百科级多维资料表。
