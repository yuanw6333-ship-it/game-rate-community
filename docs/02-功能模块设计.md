# GameRate 游戏评分社区 V1 功能模块设计

## 1. 用户模块

### 功能范围

- 用户注册。
- 用户登录。
- 获取当前用户信息。
- 修改用户昵称、头像、简介。
- 用户退出登录。
- 用户权限区分：普通用户、管理员。

### 设计说明

用户模块是系统的身份基础。普通用户可以浏览游戏、评分、评论和收藏；管理员可以进入后台管理基础数据。V1 只做普通用户和管理员两类角色，不设计复杂角色权限系统。

### 主要页面或入口

- Web 登录注册页。
- Web 个人中心页。
- 小程序个人中心页。
- 后台管理员登录页。

## 2. 游戏信息模块

### 功能范围

- 游戏列表。
- 游戏详情。
- 游戏分类。
- 游戏标签。
- 游戏封面。
- 游戏简介。
- 游戏发行日期。
- 游戏平台。
- 游戏厂商。
- 游戏综合评分。

### 设计说明

游戏信息模块是项目核心内容。游戏详情页需要展示游戏名称、原名、封面、简介、开发商、发行商、发行日期、平台、分类、标签、平均评分、评分人数、评论数量和收藏数量。

V1 中游戏资料以后台手动维护为主，后续再考虑第三方数据导入。

## 3. 游戏评分模块

### 功能范围

- 用户对游戏评分。
- 修改评分。
- 删除评分。
- 统计平均分。
- 统计评分人数。
- 防止同一用户重复评分。

### 设计说明

一个用户对同一游戏只能保留一条评分记录。用户重新评分时更新原记录，不新增重复数据。游戏表中保留平均分和评分人数，方便列表和排行榜快速展示。

评分建议采用 0 到 10 分制，可支持 0.5 分粒度。

## 4. 游戏评论模块

### 功能范围

- 发布评论。
- 查看评论列表。
- 删除自己的评论。
- 管理员删除违规评论。
- 评论分页。
- 评论时间排序。

### 设计说明

评论用于表达玩家对游戏的文字评价。V1 评论只支持一级评论，不做楼中楼、点赞通知和复杂社区互动。评论列表默认按发布时间倒序展示。

管理员可以隐藏或删除违规评论，普通用户只能删除自己的评论。

## 5. 游戏收藏模块

### 功能范围

- 收藏游戏。
- 取消收藏。
- 查看我的收藏列表。

### 设计说明

收藏用于帮助用户保存感兴趣的游戏。一个用户对同一游戏只能收藏一次。游戏表中保留收藏数量，方便详情页和排行榜展示。

## 6. 排行榜模块

### 功能范围

- 高评分游戏榜。
- 热门评论游戏榜。
- 最新发布游戏榜。
- 收藏数排行榜。

### 设计说明

排行榜用于帮助用户快速发现热门或高质量游戏。V1 排行榜优先基于数据库字段排序实现，不引入复杂推荐算法。

- 高评分游戏榜：按平均评分和评分人数排序。
- 热门评论游戏榜：按评论数量排序。
- 最新发布游戏榜：按发行日期或创建时间排序。
- 收藏数排行榜：按收藏数量排序。

## 7. 搜索模块

### 功能范围

- 按游戏名称搜索。
- 按分类筛选。
- 按标签筛选。
- 按平台筛选。

### 设计说明

V1 搜索以数据库查询为主，支持关键词、分类、标签、平台等组合条件。后续数据量变大后，可以扩展 Elasticsearch 或其他搜索方案。

## 8. 后台管理模块

### 功能范围

- 管理员登录。
- 新增游戏。
- 修改游戏信息。
- 删除游戏。
- 管理分类。
- 管理标签。
- 管理评论。

### 设计说明

后台管理模块服务于项目管理员，主要维护基础数据和内容安全。V1 后台只做基础 CRUD 和评论管理，不做复杂权限、审批流、运营配置和数据看板。

## 9. Web 前端模块

### 功能范围

- 首页。
- 游戏列表页。
- 游戏详情页。
- 登录注册页。
- 我的收藏页。
- 后台管理页。

### 设计说明

Web 用户端用于展示核心体验，后台管理页用于管理员维护数据。V1 页面以完成闭环流程为目标，优先保证可用性和清晰的信息结构。

## 10. 微信小程序端模块

### 功能范围

- 首页。
- 游戏列表。
- 游戏详情。
- 评分评论。
- 我的收藏。
- 个人中心。

### 设计说明

小程序端前期只预留结构和接口适配思路，不急于开发完整功能。后续在 Web 端和后端接口稳定后，再逐步实现小程序端页面。
