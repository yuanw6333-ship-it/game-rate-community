# GameRate 游戏评分社区V1

## 1. 项目概述

**项目名称：** GameRate 游戏评分社区V1

**项目类型：** 前后端分离游戏评分社区项目

**项目目标：**

GameRate 是一个面向游戏玩家的评分与讨论社区。用户可以浏览游戏、搜索游戏、查看游戏详情、给游戏评分、发表评论、收藏游戏，并在个人中心查看自己的评分和收藏记录。管理员可以通过后台管理游戏数据、用户数据和评论内容。

V1 阶段的核心目标不是追求功能复杂，而是先完成一个可以运行、可以演示、可以写进简历的完整项目闭环。

---

## 2. 项目定位

GameRate V1 定位为：

> 一个类似“豆瓣评分 + 游戏资料库 + 轻量评论社区”的游戏评分网站。

V1 阶段重点实现：

1. 用户注册登录
2. 游戏信息展示
3. 游戏搜索与筛选
4. 用户评分
5. 用户评论
6. 用户收藏
7. 后台游戏管理
8. 基础后台管理
9. 为后续微信小程序端和部署上线预留接口能力

---

## 3. V1 阶段开发目标

V1 阶段需要做到：

- 后端 Spring Boot 项目可以正常运行
- MySQL 数据库表结构完整
- 用户可以注册、登录、退出
- 用户可以浏览游戏列表和游戏详情
- 用户可以对游戏评分
- 用户可以发表评论
- 用户可以收藏游戏
- 管理员可以维护游戏数据
- 接口可以通过 Swagger / Knife4j 或 Apifox 测试
- 项目结构清晰，适合后续扩展 Web 前端、小程序端和云端部署

## 6.5 评分模块

### 功能列表

- 用户给游戏评分

- 查询游戏平均分
- 查询游戏评分人数
- 查看我的评分记录

### 核心业务规则

- 用户必须登录后才能评分
- 一个用户对一个游戏只能有一条评分记录
- 评分范围为 1 到 10 分
- 用户可以修改自己的评分
- 用户评分后需要重新计算游戏平均分和评分人数
- 游戏详情页展示平均评分和评分人数

### 推荐接口

```http
POST /api/ratings
PUT  /api/ratings/{gameId}
GET  /api/ratings/game/{gameId}/me
GET  /api/ratings/me
```

### 提交评分请求示例

```json
{
  "gameId": 1,
  "score": 9
}
```

## 10. 核心业务流程

## 10.1 用户注册流程

```text
用户输入用户名、密码、昵称
后端校验参数
检查用户名是否已存在
密码加密
保存用户信息
返回注册成功
```

## 10.2 用户登录流程

```text
用户输入用户名和密码
后端查询用户是否存在
校验密码是否正确
判断用户状态是否正常
生成 JWT Token
返回 Token 和用户信息
```

## 10.3 用户评分流程

```text
用户登录
进入游戏详情页
选择评分
提交评分
后端判断该用户是否已经评分
未评分则新增评分记录
已评分则更新评分记录
重新计算游戏平均分
更新游戏表 average_score 和 rating_count
返回最新评分信息
```

## 10.4 用户评论流程

```text
用户登录
进入游戏详情页
输入评论内容
提交评论
后端校验评论内容
保存评论
游戏评论数 +1
返回评论成功
```

## 10.5 用户收藏流程

```text
用户登录
进入游戏详情页
点击收藏
后端判断是否已收藏
未收藏则新增收藏记录
已收藏则取消收藏
更新游戏收藏数
返回收藏状态
```

## 10.6 管理员新增游戏流程

```text
管理员登录后台
进入游戏管理页面
点击新增游戏
填写游戏名称、简介、分类、平台、封面等信息
提交保存
后端保存游戏数据
用户端游戏列表可以看到该游戏
```

## 15. 简历描述初版

### 项目名称

GameRate 游戏评分社区

### 项目描述

GameRate 是一个基于 Spring Boot + Vue3 的前后端分离游戏评分社区，支持用户注册登录、游戏浏览、搜索筛选、评分、评论、收藏、后台游戏管理等功能。系统使用 JWT 实现登录鉴权，使用 MyBatis-Plus 完成数据持久化，使用统一返回结果和全局异常处理提升接口规范性，并为后续微信小程序端和云端部署预留扩展能力。

### 技术栈

Java 17、Spring Boot、Spring MVC、MyBatis-Plus、MySQL、JWT、Spring Validation、Lombok、Swagger / Knife4j、Vue3、Element Plus、Axios、Git

### 项目亮点

1. 使用 JWT + 拦截器实现用户登录鉴权，限制未登录用户访问评分、评论、收藏等接口。
2. 使用 MyBatis-Plus 实现游戏列表分页、条件筛选、详情查询、评分查询等功能。
3. 设计用户评分业务规则，限制同一用户对同一游戏重复评分，并支持修改评分后重新计算平均分。
4. 使用统一 Result 返回结构、全局异常处理和参数校验，提高接口规范性。
5. 后台管理端支持游戏、分类、平台、用户和评论管理，形成完整的前后台业务闭环。
6. 项目接口设计兼容 Web 用户端和微信小程序端，后续可扩展为多端项目。
