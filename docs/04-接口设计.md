# GameRate 游戏评分社区 V1 接口设计

## 1. 接口通用约定

- 接口风格：RESTful API
- 请求前缀：`/api`
- 请求格式：`application/json`
- 返回格式：统一 `Result`
- 认证方式：JWT Token
- 登录请求头：`Authorization: Bearer <token>`
- 分页参数：`pageNum`、`pageSize`

### 通用返回结构

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "timestamp": "2026-05-29T10:00:00"
}
```

## 6. 用户端游戏接口

### 6.1 游戏分页列表

| 项目 | 内容 |
|---|---|
| 接口说明 | 分页查询正常上架游戏 |
| 请求方式 | GET |
| 请求路径 | `/api/games` |
| 请求参数 | `keyword`、`categoryId`、`platformId`、`sort`、`pageNum`、`pageSize` |
| 返回数据说明 | `PageResult<GameListVO>` |
| 权限要求 | 无需登录 |

参数说明：

| 参数 | 说明 |
|---|---|
| `keyword` | 游戏名称或原名关键词 |
| `categoryId` | 分类 ID |
| `platformId` | 平台 ID |
| `sort` | `default`、`latest`、`score`、`hot` |
| `pageNum` | 页码，默认 1 |
| `pageSize` | 每页数量，默认 10，最大 100 |

排序说明：

| sort | 排序规则 |
|---|---|
| `default` | 按 `create_time` 降序 |
| `latest` | 按 `release_date` 降序，再按 `create_time` 降序 |
| `score` | 按 `average_score` 降序，再按 `rating_count` 降序 |
| `hot` | 按 `view_count`、`favorite_count`、`comment_count` 降序 |

### 6.2 游戏详情

| 项目 | 内容 |
|---|---|
| 接口说明 | 查询正常上架游戏详情 |
| 请求方式 | GET |
| 请求路径 | `/api/games/{id}` |
| 请求参数 | 路径参数 `id` |
| 返回数据说明 | `GameDetailVO` |
| 业务规则 | 游戏不存在或已下架时抛出 `BusinessException`；查询成功后 `view_count + 1` |
| 权限要求 | 无需登录 |

## 8. RAWG 游戏资料导入接口

RAWG 接口属于后台能力，统一需要登录，请求头需要携带：

```text
Authorization: Bearer <token>
```

### 8.1 RAWG 搜索游戏

| 项目 | 内容 |
|---|---|
| 接口说明 | 根据关键词调用 RAWG 搜索游戏资料，返回候选游戏列表 |
| 请求方式 | GET |
| 请求路径 | `/api/admin/rawg/search` |
| 请求参数 | `keyword`、`pageNum`、`pageSize` |
| 返回数据说明 | `RawgGameSearchVO` 列表，包含 `rawgId`、`name`、`released`、`backgroundImage`、`rating`、`metacritic`、`platforms`、`genres` |
| 权限要求 | 需要登录 |

参数说明：

| 参数 | 说明 |
|---|---|
| `keyword` | 搜索关键词，必填 |
| `pageNum` | 页码，默认 1 |
| `pageSize` | 每页数量，默认 10，最大 50 |

### 8.2 RAWG 游戏详情预览

| 项目 | 内容 |
|---|---|
| 接口说明 | 根据 RAWG 游戏 ID 查询游戏详情，用于导入前预览 |
| 请求方式 | GET |
| 请求路径 | `/api/admin/rawg/games/{rawgId}` |
| 请求参数 | 路径参数 `rawgId` |
| 返回数据说明 | `RawgGameDetailVO`，包含 `rawgId`、`slug`、`name`、`description`、`released`、`backgroundImage`、`website`、`rating`、`metacritic`、`developers`、`publishers`、`platforms`、`genres` |
| 权限要求 | 需要登录 |

### 8.3 导入 RAWG 游戏到本地数据库

| 项目 | 内容 |
|---|---|
| 接口说明 | 根据 RAWG 游戏 ID 拉取详情并写入本地 `game` 表 |
| 请求方式 | POST |
| 请求路径 | `/api/admin/rawg/import` |
| 请求参数 | `RawgImportDTO` |
| 返回数据说明 | `RawgImportResultVO`，包含 `gameId`、`imported`、`existed`、`message` |
| 权限要求 | 需要登录 |

请求参数核心字段：

| 字段 | 说明 |
|---|---|
| `rawgId` | RAWG 游戏 ID，必填 |
| `categoryId` | 本地游戏分类 ID，必填且必须存在 |
| `platformId` | 本地游戏平台 ID，必填且必须存在 |
| `status` | 导入后的游戏状态，默认 1 |
| `overwrite` | 预留字段；V1 重复导入时不覆盖本地数据，直接返回已有 `gameId` |

导入字段映射：

| RAWG 字段 | 本地 `game` 字段 |
|---|---|
| `id` | `source_id` |
| 固定值 `RAWG` | `source_type` |
| `slug` | 用于拼接 `source_url` |
| `name` | `name` |
| `description_raw` / `description` | 去除 HTML 后保存到 `description` |
| `released` | `release_date` |
| `background_image` | `cover_url`、`background_url` |
| `rating` | `rawg_rating` |
| `metacritic` | `metacritic_score` |
| `developers` | `developer`，多个值用英文逗号拼接 |
| `publishers` | `publisher`，多个值用英文逗号拼接 |

重复导入策略：

- 当本地已存在 `source_type = RAWG` 且 `source_id = rawgId` 的游戏时，不新增数据。
- 重复导入不抛异常，直接返回已有 `gameId`，`imported=false`，`existed=true`。
- V1 不使用 `overwrite` 覆盖已有游戏资料，也不会覆盖 `average_score`、`rating_count`、`view_count`、`favorite_count`、`comment_count` 等站内统计字段。

## 9. 游戏评分接口

评分接口统一需要登录，请求头需要携带：

```text
Authorization: Bearer <token>
```

### 9.1 提交或修改游戏评分

| 项目 | 内容 |
|---|---|
| 接口说明 | 当前用户提交游戏评分；已评分时更新原评分记录 |
| 请求方式 | POST |
| 请求路径 | `/api/ratings` |
| 请求参数 | `gameId`、`score` |
| 返回数据说明 | `GameRatingVO`，包含 `gameId`、`score`、`ratingTime`、`averageScore`、`ratingCount` |
| 权限要求 | 需要登录 |

业务规则：

- `gameId` 和 `score` 必填。
- `score` 范围为 1 到 10。
- 游戏必须存在且处于正常上架状态。
- 一个用户对一个游戏只能保留一条评分记录；重复评分时更新原记录。
- 新增或修改评分后，从 `game_rating` 表重新聚合计算 `AVG(score)` 和 `COUNT(*)`。
- `average_score` 保留 1 位小数，并同步更新 `game.average_score`、`game.rating_count`、`game.update_time`。

请求体示例：

```json
{
  "gameId": 1,
  "score": 9.5
}
```

### 9.2 查询当前用户对指定游戏的评分

| 项目 | 内容 |
|---|---|
| 接口说明 | 查询当前登录用户是否已对指定游戏评分 |
| 请求方式 | GET |
| 请求路径 | `/api/ratings/game/{gameId}/me` |
| 请求参数 | 路径参数 `gameId` |
| 返回数据说明 | `MyRatingVO`；未评分时 `hasRated=false`，`score` 和 `ratingTime` 为空 |
| 权限要求 | 需要登录 |

### 9.3 查询我的评分记录

| 项目 | 内容 |
|---|---|
| 接口说明 | 分页查询当前登录用户的评分记录 |
| 请求方式 | GET |
| 请求路径 | `/api/ratings/me` |
| 请求参数 | `pageNum`、`pageSize` |
| 返回数据说明 | `PageResult<MyRatingVO>`，包含游戏 ID、游戏名称、封面、用户评分和评分时间 |
| 排序规则 | 按评分记录 `update_time` 降序 |
| 权限要求 | 需要登录 |

## 10. 游戏评论接口

评论接口统一需要登录，请求头需要携带：

```text
Authorization: Bearer <token>
```

### 10.1 提交评论

| 项目 | 内容 |
|---|---|
| 接口说明 | 当前用户对正常上架游戏发表评论 |
| 请求方式 | POST |
| 请求路径 | `/api/comments` |
| 请求参数 | `gameId`、`content` |
| 返回数据说明 | `GameCommentVO`，包含评论 ID、游戏 ID、用户信息、评论内容和评论时间 |
| 权限要求 | 需要登录 |

业务规则：

- `gameId` 必填。
- `content` 不能为空，长度为 1 到 500。
- 游戏必须存在且处于正常上架状态。
- 新增评论和更新 `game.comment_count` 在同一事务中完成。
- `game.comment_count` 根据有效评论记录重新统计。

请求体示例：

```json
{
  "gameId": 1,
  "content": "这是一条游戏评论。"
}
```

### 10.2 删除评论

| 项目 | 内容 |
|---|---|
| 接口说明 | 当前用户删除自己的评论 |
| 请求方式 | DELETE |
| 请求路径 | `/api/comments/{commentId}` |
| 请求参数 | 路径参数 `commentId` |
| 返回数据说明 | 删除结果 |
| 权限要求 | 需要登录 |

业务规则：

- 普通用户只能删除自己的评论。
- 删除使用逻辑删除，不物理移除数据。
- 删除评论和更新 `game.comment_count` 在同一事务中完成。
- 当前项目尚未实现管理员登录和管理员身份上下文，因此管理员删除任意评论暂未接入；后续管理员鉴权模块完成后扩展。

### 10.3 获取游戏评论列表

| 项目 | 内容 |
|---|---|
| 接口说明 | 分页查询指定游戏的有效评论 |
| 请求方式 | GET |
| 请求路径 | `/api/comments/game/{gameId}` |
| 请求参数 | 路径参数 `gameId`，查询参数 `pageNum`、`pageSize` |
| 返回数据说明 | `PageResult<GameCommentVO>`，每条评论包含评论 ID、用户昵称、用户头像、评论内容和评论时间 |
| 排序规则 | 按评论 `create_time` 降序 |
| 权限要求 | 需要登录 |

## 11. 游戏收藏接口

收藏接口统一需要登录，请求头需要携带：

```text
Authorization: Bearer <token>
```

### 11.1 收藏游戏

| 项目 | 内容 |
|---|---|
| 接口说明 | 当前用户收藏正常上架游戏 |
| 请求方式 | POST |
| 请求路径 | `/api/favorites/{gameId}` |
| 请求参数 | 路径参数 `gameId` |
| 返回数据说明 | `FavoriteStatusVO`，包含 `hasFavorited`、`gameId`、`favoriteCount` |
| 权限要求 | 需要登录 |

业务规则：

- 游戏必须存在且处于正常上架状态。
- 一个用户不能重复收藏同一个游戏。
- 已收藏时直接返回收藏状态，不新增重复记录。
- 曾取消收藏时恢复原收藏记录。
- 收藏记录更新和重新统计 `game.favorite_count` 在同一事务中完成。

### 11.2 取消收藏

| 项目 | 内容 |
|---|---|
| 接口说明 | 当前用户取消收藏游戏 |
| 请求方式 | DELETE |
| 请求路径 | `/api/favorites/{gameId}` |
| 请求参数 | 路径参数 `gameId` |
| 返回数据说明 | `FavoriteStatusVO`，包含 `hasFavorited=false`、`gameId`、`favoriteCount` |
| 权限要求 | 需要登录 |

业务规则：

- 游戏必须存在。
- 未收藏该游戏时直接返回未收藏状态，不抛异常。
- 已收藏时将收藏记录 `status` 修改为 0。
- 取消收藏和重新统计 `game.favorite_count` 在同一事务中完成。

### 11.3 查询收藏状态

| 请求参数 | 路径参数 `gameId` |
| 返回数据说明 | `FavoriteStatusVO`，包含 `hasFavorited`、`gameId`、`favoriteCount` |
| 权限要求 | 需要登录 |

### 11.4 查询我的收藏列表

## 12. 游戏排行榜接口

排行榜接口无需登录，统一返回 `PageResult<GameRankingVO>`。榜单只展示 `status=1` 的正常上架游戏。

`GameRankingVO` 包含：

- `gameId`
- `name`
- `coverUrl`
- `averageScore`
- `ratingCount`
- `favoriteCount`
- `commentCount`
- `viewCount`
- `releaseDate`

### 12.1 高分榜

| 项目 | 内容 |
|---|---|
| 请求方式 | GET |
| 请求路径 | `/api/rankings/top-score` |
| 请求参数 | `pageNum`、`pageSize` |
