# GameRate 游戏评分社区 V1 接口设计

## 1. 接口通用约定

- 接口风格：RESTful API
- 请求前缀：`/api`
- 请求格式：`application/json`
- 返回格式：统一 `Result`
- 认证方式：JWT Token
- 登录请求头：`Authorization: Bearer <token>`
- 分页参数：`pageNum`、`pageSize`

### 通用返回结构

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "timestamp": "2026-05-29T10:00:00"
}
```

## 6. 用户端游戏接口

### 6.1 游戏分页列表

| 项目 | 内容 |
|---|---|
| 接口说明 | 分页查询正常上架游戏 |
| 请求方式 | GET |
| 请求路径 | `/api/games` |
| 请求参数 | `keyword`、`categoryId`、`platformId`、`sort`、`pageNum`、`pageSize` |
| 返回数据说明 | `PageResult<GameListVO>` |
| 权限要求 | 无需登录 |

参数说明：

| 参数 | 说明 |
|---|---|
| `keyword` | 游戏名称或原名关键词 |
| `categoryId` | 分类 ID |
| `platformId` | 平台 ID |
| `sort` | `default`、`latest`、`score`、`hot` |
| `pageNum` | 页码，默认 1 |
| `pageSize` | 每页数量，默认 10，最大 100 |

排序说明：

| sort | 排序规则 |
|---|---|
| `default` | 按 `create_time` 降序 |
| `latest` | 按 `release_date` 降序，再按 `create_time` 降序 |
| `score` | 按 `average_score` 降序，再按 `rating_count` 降序 |
| `hot` | 按 `view_count`、`favorite_count`、`comment_count` 降序 |

### 6.2 游戏详情

| 项目 | 内容 |
|---|---|
| 接口说明 | 查询正常上架游戏详情 |
| 请求方式 | GET |
| 请求路径 | `/api/games/{id}` |
| 请求参数 | 路径参数 `id` |
| 返回数据说明 | `GameDetailVO` |
| 业务规则 | 游戏不存在或已下架时抛出 `BusinessException`；查询成功后 `view_count + 1` |
| 权限要求 | 无需登录 |

后台接口统一需要登录，请求头需要携带：


### 7.1 后台分页查询游戏

| 项目 | 内容 |

| 返回数据说明 | `PageResult<GameListVO>` |
| 权限要求 | 需要登录 |

### 7.2 新增游戏

| 项目 | 内容 |
|---|---|
| 接口说明 | 后台新增游戏 |
| 请求方式 | POST |
| 请求路径 | `/api/admin/games` |
| 请求参数 | `GameCreateDTO` |
| 返回数据说明 | `GameDetailVO` |

请求参数核心字段：

| 字段 | 说明 |
|---|---|
| `name` | 游戏名称，必填 |
| `categoryId` | 分类 ID，必填且必须存在 |
| `platformId` | 平台 ID，必填且必须存在 |
| `status` | 游戏状态，默认 1 |
| `coverUrl` | 游戏封面图 |
| `backgroundUrl` | 游戏背景图 |

### 7.3 修改游戏

| 项目 | 内容 |
|---|---|
| 接口说明 | 后台修改游戏 |
| 请求方式 | PUT |
| 请求路径 | `/api/admin/games/{id}` |
| 请求参数 | 路径参数 `id`，请求体 `GameUpdateDTO` |
| 返回数据说明 | `GameDetailVO` |
| 业务规则 | 游戏必须存在；传入 `categoryId` 时分类必须存在；传入 `platformId` 时平台必须存在；只更新允许修改的字段 |
| 权限要求 | 需要登录 |

### 7.4 删除或下架游戏

| 项目 | 内容 |
|---|---|
| 接口说明 | 后台删除或下架游戏 |
| 请求方式 | DELETE |
| 请求路径 | `/api/admin/games/{id}` |
| 请求参数 | 路径参数 `id` |
| 返回数据说明 | 删除结果 |
| 业务规则 | 不物理删除游戏，不删除评分、评论、收藏数据；当前实现为将 `status` 修改为 0 |
| 权限要求 | 需要登录 |

## 8. RAWG 游戏资料导入接口

RAWG 接口属于后台能力，统一需要登录，请求头需要携带：

```text
Authorization: Bearer <token>
```

### 8.1 RAWG 搜索游戏

| 项目 | 内容 |
|---|---|
| 接口说明 | 根据关键词调用 RAWG 搜索游戏资料，返回候选游戏列表 |
| 请求方式 | GET |
| 请求路径 | `/api/admin/rawg/search` |
| 请求参数 | `keyword`、`pageNum`、`pageSize` |
| 返回数据说明 | `RawgGameSearchVO` 列表，包含 `rawgId`、`name`、`released`、`backgroundImage`、`rating`、`metacritic`、`platforms`、`genres` |
| 权限要求 | 需要登录 |

参数说明：

| 参数 | 说明 |
|---|---|
| `keyword` | 搜索关键词，必填 |
| `pageNum` | 页码，默认 1 |
| `pageSize` | 每页数量，默认 10，最大 50 |

### 8.2 RAWG 游戏详情预览

| 项目 | 内容 |
|---|---|
| 接口说明 | 根据 RAWG 游戏 ID 查询游戏详情，用于导入前预览 |
| 请求方式 | GET |
| 请求路径 | `/api/admin/rawg/games/{rawgId}` |
| 请求参数 | 路径参数 `rawgId` |
| 返回数据说明 | `RawgGameDetailVO`，包含 `rawgId`、`slug`、`name`、`description`、`released`、`backgroundImage`、`website`、`rating`、`metacritic`、`developers`、`publishers`、`platforms`、`genres` |
| 权限要求 | 需要登录 |

### 8.3 导入 RAWG 游戏到本地数据库

| 项目 | 内容 |
|---|---|
| 接口说明 | 根据 RAWG 游戏 ID 拉取详情并写入本地 `game` 表 |
| 请求方式 | POST |
| 请求路径 | `/api/admin/rawg/import` |
| 请求参数 | `RawgImportDTO` |
| 返回数据说明 | `RawgImportResultVO`，包含 `gameId`、`imported`、`existed`、`message` |
| 权限要求 | 需要登录 |

请求参数核心字段：

| 字段 | 说明 |
|---|---|
| `rawgId` | RAWG 游戏 ID，必填 |
| `categoryId` | 本地游戏分类 ID，必填且必须存在 |
| `platformId` | 本地游戏平台 ID，必填且必须存在 |
| `status` | 导入后的游戏状态，默认 1 |
| `overwrite` | 预留字段；V1 重复导入时不覆盖本地数据，直接返回已有 `gameId` |

导入字段映射：

| RAWG 字段 | 本地 `game` 字段 |
|---|---|
| `id` | `source_id` |
| 固定值 `RAWG` | `source_type` |
| `slug` | 用于拼接 `source_url` |
| `name` | `name` |
| `description_raw` / `description` | 去除 HTML 后保存到 `description` |
| `released` | `release_date` |
| `background_image` | `cover_url`、`background_url` |
| `rating` | `rawg_rating` |
| `metacritic` | `metacritic_score` |
| `developers` | `developer`，多个值用英文逗号拼接 |
| `publishers` | `publisher`，多个值用英文逗号拼接 |

重复导入策略：

- 当本地已存在 `source_type = RAWG` 且 `source_id = rawgId` 的游戏时，不新增数据。
- 重复导入不抛异常，直接返回已有 `gameId`，`imported=false`，`existed=true`。
- V1 不使用 `overwrite` 覆盖已有游戏资料，也不会覆盖 `average_score`、`rating_count`、`view_count`、`favorite_count`、`comment_count` 等站内统计字段。

## 9. 游戏评分接口

评分接口统一需要登录，请求头需要携带：

```text
Authorization: Bearer <token>
```

### 9.1 提交或修改游戏评分

| 项目 | 内容 |
|---|---|
| 接口说明 | 当前用户提交游戏评分；已评分时更新原评分记录 |
| 请求方式 | POST |
| 请求路径 | `/api/ratings` |
| 请求参数 | `gameId`、`score` |
| 返回数据说明 | `GameRatingVO`，包含 `gameId`、`score`、`ratingTime`、`averageScore`、`ratingCount` |
| 权限要求 | 需要登录 |

业务规则：

- `gameId` 和 `score` 必填。
- `score` 范围为 1 到 10。
- 游戏必须存在且处于正常上架状态。
- 一个用户对一个游戏只能保留一条评分记录；重复评分时更新原记录。
- 新增或修改评分后，从 `game_rating` 表重新聚合计算 `AVG(score)` 和 `COUNT(*)`。
- `average_score` 保留 1 位小数，并同步更新 `game.average_score`、`game.rating_count`、`game.update_time`。

请求体示例：

```json
{
  "gameId": 1,
  "score": 9.5
}
```

### 9.2 查询当前用户对指定游戏的评分

| 项目 | 内容 |
|---|---|
| 接口说明 | 查询当前登录用户是否已对指定游戏评分 |
| 请求方式 | GET |
| 请求路径 | `/api/ratings/game/{gameId}/me` |
| 请求参数 | 路径参数 `gameId` |
| 返回数据说明 | `MyRatingVO`；未评分时 `hasRated=false`，`score` 和 `ratingTime` 为空 |
| 权限要求 | 需要登录 |

### 9.3 查询我的评分记录

| 项目 | 内容 |
|---|---|
| 接口说明 | 分页查询当前登录用户的评分记录 |
| 请求方式 | GET |
| 请求路径 | `/api/ratings/me` |
| 请求参数 | `pageNum`、`pageSize` |
| 返回数据说明 | `PageResult<MyRatingVO>`，包含游戏 ID、游戏名称、封面、用户评分和评分时间 |
| 排序规则 | 按评分记录 `update_time` 降序 |
| 权限要求 | 需要登录 |
